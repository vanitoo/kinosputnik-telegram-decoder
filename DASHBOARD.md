# KINOSPUTNIK Orbit Monitor

## Запуск

В первом терминале оставьте существующий сборщик:

    python main.py watch --history 1000 --topic-name KINOSPUTNIK

Во втором:

    python dashboard.py

Откройте http://127.0.0.1:8080. Параметры: --db, --port, --limit (1..20000).
Только localhost, база SQLite читается в режиме read-only, WAL поддерживается. Авторизация Telegram и сборщик не изменены. Дашборд не требует новых обязательных зависимостей. OSM/Leaflet загружаются только по кнопке, офлайн-карта схематична. Данные обновляются каждые 15 секунд; при ошибке остаётся последняя выборка.

Фильтры станции, периода (от последнего приёма), типа, RAW/CAN/ID; воспроизведение, масштабирование, геометрическая зона радиогоризонта, графики, журнал, CSV и RAW-инспектор. Паузы >180 сек и пересечение антимеридиана разрывают линии. Координаты взяты из сообщений, не из GPS спутника. Недостоверные датчики исключаются из графиков.

Автономный снимок:

    python dashboard.py --export map.html

Снимок содержит RAW и координаты, не публикуйте его без необходимости. Прогноз в автономном снимке выключен.

## Прогноз орбиты (опционально)

    python -m pip install skyfield

Сохраните проверенный TLE именно KINOSPUTNIK в data/kinosputnik.tle (две строки TLE, имя необязательно), либо укажите --tle путь. Не используется автоматическое угадывание NORAD. В панели нажмите «Рассчитать на 3 часа», задав свои координаты (по умолчанию пример Москвы). Через Skyfield/SGP4 строится расчётная трасса на 3 часа, события пролёта на 24 часа (элевация от 10°). TLE старше 14 суток блокируется; даже свежий TLE не гарантирует точность. Расчёт не подменяет реальные приёмы.

## Инспектор расширенных данных

При разборе 48/109 Б проверяются последовательность CAN ID, длина, адрес узла и маркер конца; CRC не проверяется. Неизвестный хвост сохраняется целиком со смещением и кандидатами CAN ID — это не полноценное декодирование. Составной маяк 109 Б берётся из существующей таблицы extended_reassembled (эвристическое сопоставление).

В расширенном маяке с префиксом 08090065:
- 8..15: предполагаемое CDS-время; проверка диапазонов и совпадения с временем приёма (не более 300 секунд);
- 16: неизвестный статус (HEX);
- 17..20: предполагаемый uptime (сек), расчётное время включения.
Эти поля экспериментальные, не официальная спецификация. Нет карты остальных полей. Значения счётчика ошибок короткого маяка не следует трактовать как количество аварий.

База с новыми типами от 17 ноября ещё не получена: неизвестные данные показываются без выдуманных физических значений. Базу, TLE и Telegram-сессию в Git не добавлять.
